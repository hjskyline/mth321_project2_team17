# mth321_project2_team17
MTH321 Project 2: Elliptic BVPs — Team 17

## Project direction

Mixed Dirichlet/Neumann/Robin boundary data for the two-dimensional Poisson problem.
Compare the prescribed one-sided and ghost-point finite-difference boundary closures.

This repository currently contains the project structure only. Solver implementation,
experiments, dependencies, report, and presentation will be added as the project develops.

## Repository structure

```text
code/       Solver implementations, experiments, tests, and future run_all.py
docs/       Model derivations, verification plans, meeting notes, and AI-use records
figures/    Figures generated by experiments
results/    Error tables, convergence data, timings, and numerical results
report/     LaTeX report, references, and contribution statements
slides/     Presentation sources and exported slides
```

Each initially empty directory contains a .gitkeep placeholder because Git tracks
files rather than empty directories. No lecture PDFs or local virtual environments
are included.

## Team Git workflow

- `main`: shared project baseline; integrate reviewed work here.
- `ziming`: Ziming Tang's personal working branch.
- Other members keep their own branches. Existing branches are preserved.
- Normally submit changes through a pull request into `main`.

Clone and select the personal branch (for a new clone only):

```bash
git clone https://github.com/hjskyline/mth321_project2_team17.git
cd mth321_project2_team17
git switch --track origin/ziming
```

Save and upload your work while on your personal branch:

```bash
git status
git add code/ docs/ figures/ results/ report/ slides/
git commit -m "Describe the change"
git push
```

Stage root-level files such as README.md explicitly when they change.
Check that no private files or credentials are staged before committing.

With a clean working tree, update main and incorporate it into your branch:

```bash
git switch main
git pull --ff-only
git switch ziming
git merge main
git push
```

If Git reports conflicts, resolve them and commit before continuing.
Switching branches changes the files in the same local directory; it does not
require a second copy of the project. Each teammate uses their own Python
environment and their own GitHub authentication.
